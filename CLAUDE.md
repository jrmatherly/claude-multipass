# CLAUDE.md

Guidance for Claude Code in this repository.

## Overview

`bin/claude-multipass` switches the Claude Desktop app between saved claude.ai accounts on one Mac without an email code, moves the Claude Code CLI's terminal login with it, and keeps every saved account's Claude Code sessions listed in the Code tab after a switch. `app/` is Claude Multipass, a menu bar app over the same script (it never touches Desktop's files itself), shipped as a notarized DMG through the `claude-multipass-app` cask. One Mac, several accounts (personal, work, a second plan). macOS only (`osascript`, `open`, `security`, Application Support paths). Runs on the system `/bin/bash` 3.2 and needs `jq`. `fzf` is optional (the picker). `usage` also needs `curl`, `openssl` and the Command Line Tools (`/usr/bin/python3` is their shim; `doctor` checks `xcode-select -p`). The CLI login's Keychain items go through `security` on PATH and nothing else.

Three Raycast script commands in `raycast/` call the tool by name (`CLAUDE_MULTIPASS_BIN` overrides it; the self-check sets it). `bin/claude-multipass --help` is the command reference; `docs/claude-multipass.md` explains the mechanism for users; `docs/research.md` is the scrubbed research the tool was built from.

## Commands

- `pnpm check` (`test/check.sh`) is the gate. It exports `LC_ALL=en_US.UTF-8` (the self-checks grep for UTF-8 glyphs) and runs `bash -n` and `shellcheck --severity=warning` on `bin/*`, `test/*.sh`, `.claude/hooks/*.sh`, `raycast/*.sh` and `scripts/*.sh`; `prettier --check` over `**/*.{js,cjs,ts,md,json,sh}`, `bin/*` and `.github/**/*.yml`; `test/claude-multipass.sh`; every hook self-check, `.claude/hooks/test-*.sh` by glob (`test-settings.sh` checks the settings wiring); a check that every `bin/` file has a comment on line 2; that `version=` in the script equals `package.json`; and `swift test --package-path app` (a debug build, under 10 s warm: 7 s measured on 2026-10-27). The app module uses SwiftUI macros whose compiler plugin only Xcode ships, so the gate exports `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer` when `xcode-select -p` is the Command Line Tools and Xcode is installed; with the Tools alone the core tests run only with `-Xswiftc -plugin-path -Xswiftc "$(xcode-select -p)/usr/lib/swift/host/plugins/testing"` and the app target does not build. CI (`.github/workflows/check.yml`) runs it on `macos-26` for PRs and pushes to `main`, with ShellCheck pinned to the release binary and checksum named in the job's `env` (`SHELLCHECK_VERSION`, `SHELLCHECK_SHA256`) and a 20-minute job timeout.
- `pnpm shots [dir]` (`test/shots.sh`, default dir `.shots/`, git-ignored) sets `DEVELOPER_DIR` as the gate does and runs `UI_SHOTS_DIR=<dir> swift test --package-path app --filter Shots`, which renders the menu bar strip (each style and usage level), the popover and each Settings tab to PNGs in light and dark from fixture state, and checks that no settings field takes focus on open or on a tab switch and that the General tab grows when Custom adds the path field. Without the variable the suite is skipped. It opens the settings window on screen for a moment and never runs the real tool. Any UI review or critique starts by rendering the branch under review this way, light and dark, before asking Jason for screenshots, and reads small PNGs zoomed (`magick <png> -scale 400% <out> 2>/dev/null`; the `2>/dev/null` hides harmless `iCCP` warnings).
- `pnpm format`: prettier `--write` over the same globs.
- One file: `bash -n <file> && shellcheck --severity=warning <file> && node_modules/.bin/prettier --check <file>`.
- `bash test/claude-multipass.sh`: the fixture self-check, exits 1 naming the first failed assertion. It never touches the real Desktop: `CLAUDE_DESKTOP_DIR`, `CLAUDE_MULTIPASS_DIR`, `CLAUDE_CLI_CONFIG` and `CLAUDE_CLI_HOME` point into a temp dir, `CLAUDE_MULTIPASS_BIN` points the Raycast scripts at the checkout, and `pgrep`, `osascript`, `pkill`, `open`, `fzf`, `security` (stateful, items under the temp dir, the Safe Storage read answered with a fixture password), `curl`, `claude` (its `auth status` answer, written per case) and `sleep` (the quit-fallback case only) are stubs on PATH (no app quit or launched, no Keychain, no network). The migration case sets `XDG_CONFIG_HOME` to the temp dir, not `HOME`, because tools on PATH read their own config from `HOME`. Details in `.claude/rules/testing.md`.
- Never run `save`, `add`, `switch`, `remove`, `sync`, `pick` or a bare `claude-multipass` (the picker switches on Enter) against the real Desktop folder from an agent: they quit the app and rewrite its login. `.claude/settings.json` asks before `save`, `add`, `switch`, `rename`, `remove`, `sync`, `usage` and `pick` by name or by any path ending in `bin/claude-multipass` (`bash bin/...` and absolute paths included), before a bare `claude-multipass` (the picker), and before `raycast/switch-claude-account.sh`, which runs a real switch. `usage` reads the Keychain and prompts the user; leave it to them. `save`, `add`, `switch`, `rename` and `remove` also read and write the CLI login's Keychain items (`rename` moves the tool's own item only, so it is on the ask list but never quits Desktop). `list`, `show` and `current` are read-only, apart from the one-time store migration.

## Architecture

```text
bin/claude-multipass     the tool, one bash script; its header comment is the tldr page
test/check.sh            pnpm check
test/claude-multipass.sh fixture self-check
raycast/                 claude-account.sh (inline, current name), claude-account-usage.sh (inline, opt-in), switch-claude-account.sh (argument, confirmation)
app/                     the menu bar app, a Swift package: Sources/MultipassCore (models, CLI runner, formatting, settings, state; Foundation only, unit tested), Sources/ClaudeMultipass (AppKit/SwiftUI shell), Tests/
scripts/                 build-app.sh (swift build, bundle, sign, optional DMG), sign-mac-app.sh (copied from ai-kb)
docs/                    claude-multipass.md (how it works, for users), research.md (scrubbed research digest), superpowers/ (specs and plans)
.claude/                 settings.json (permissions, hooks), hooks/ (lint and commit gate with self-checks), rules/, skills/, agents/
.github/workflows/       check.yml (pnpm check on PRs and main), release.yml (on v* tags: build, sign, notarize, upload the DMG)
private/                 git-ignored research and notes, never published
```

Storage model:

- A Desktop login is three `config.json` keys (`oauth:tokenCache`, `oauth:tokenCacheV2`, `lastKnownAccountUuid`) plus the `Cookies` and `Cookies-journal` files (in `Network/` when that folder exists), all under `~/Library/Application Support/Claude` (`CLAUDE_DESKTOP_DIR` overrides). The app encrypts them with its "Claude Safe Storage" login-Keychain key; the tool copies them as opaque bytes.
- The Code tab lists one `claude-code-sessions/<account>/<org>/local_<id>.json` pointer per session, with no account field inside, so a copied pointer shows the session to another account. A `deleted_<id>` file beside them is a tombstone.
- The Claude Code CLI's login is a login-Keychain item (service `Claude Code-credentials`, account the macOS user name, a JSON blob with `claudeAiOauth` tokens and shared MCP keys) plus `oauthAccount` in `~/.claude.json` (`CLAUDE_CLI_CONFIG` overrides; `CLAUDE_CLI_HOME` is the lock dirs' home). A profile keeps the account part of the item in a Keychain item of its own (service `claude-multipass`, account the profile name) and the identity in `cli.json`; `save` captures it only when `oauthAccount.accountUuid` equals Desktop's live account, `switch` swaps it back under the CLI's lock dirs, keeping the shared keys. `security` on PATH is the only Keychain accessor, and a CLI item too long for a `security -i` line (4000 bytes) is written with its hex on `security`'s argv, as Claude Code writes its own; the measured partition facts are in `.claude/rules/desktop-internals.md`.
- Transcripts are shared in `~/.claude/projects` and never touched.
- Profiles live in `${CLAUDE_MULTIPASS_DIR:-${XDG_CONFIG_HOME:-~/.config}/claude-multipass}/profiles/<name>/` (`config.json` with the three keys, the cookie files, `meta.json` with `account` and `savedAt`), mode 0600 and 0700. `backups/` beside it holds the login each switch or add replaced (`login-*`, newest ten) and profiles replaced by `save --force` or `remove` (`profile-*`, newest ten).
- A store left at `~/.config/dotfiles/claude-desktop-accounts` (plus `-backups`) by the tool's earlier life in a dotfiles repo is moved into place once, on the first run that finds it, no new store and no `CLAUDE_MULTIPASS_DIR`.

The verified Desktop and CLI internals, with evidence labels, are in `.claude/rules/desktop-internals.md`. Do not re-derive them.

## Conventions

- Shell style, as in the script: `#!/bin/bash`, `set -euo pipefail`, inline `tput` helpers (`info`, `warning`, `fail`), no sourced library. The header comment block is the tldr page (one `- description:` line and a backticked command per entry, then `---` and the mechanism notes), so keep it accurate when behaviour changes. Comments explain the non-obvious why (a macOS quirk, a bash 3.2 limit, the app's file format), not what the code does.
- Prettier with `prettier-plugin-sh` (`prettier.config.cjs`: `singleQuote`, `semi: false`; Markdown `printWidth: 70`, `proseWrap: never`). ShellCheck at `--severity=warning` with `check-unassigned-uppercase` (`.shellcheckrc`). `.prettierignore` skips `CLAUDE.md`, `.serena/`, `private/`, `.remember/`, `logs/`, `.claude/settings.local.json`, `.superpowers/` and `app/.build/`; don't hand-format them.
- Prose, in docs, comments and replies: no em-dashes, short declarative sentences, sentence-case headings, straight quotes, facts and paths over adjectives.
- Commit subjects are short, imperative, sentence case, with no conventional-commit prefix.
- Docs mirror behaviour: a change to what the script does edits `README.md` or `docs/` in the same commit. The commit-gate hook (`.claude/hooks/commit-gate.sh`) runs `pnpm check` before every `git commit` (and the `--continue` of merge, cherry-pick, revert, rebase and am) and reminds about this when `bin/claude-multipass` changed without a README or docs change. It also reminds when `bin/` or `app/Sources/` changed without a `CHANGELOG.md` change: a user-visible change adds its line under `## Unreleased` in its own PR, and a tooling-only change (hooks, CI, tests, scripts) adds none.
- Every new command, option or refusal gets a case in `test/claude-multipass.sh`.

## Safety rails

Keep these when changing the script. The rules a reviewer rejects a change for are in `.claude/rules/safety-and-terms.md`.

- Refusals, each lifted only by `--force`: `save` over a profile that holds a different account, or under a second name for an account already saved (the other profile moves to `backups/`); `switch` or `add` away from a login that was never saved; `sync` while Desktop runs. `--force` is rejected for any other command. `save` refuses when signed out, before quitting the app.
- `backup_login` copies `config.json` and the cookies into `backups/login-<timestamp>-<pid>` before every merge into `config.json` (`switch`, `add`).
- `index_sync` is add-only: it copies a pointer only when the source is newer (`lastActivityAt`, else mtime), skips any id with a `deleted_*` tombstone, and never deletes or symlinks.
- Desktop is quit before any write (`osascript` quit, then `pkill` after 8 s, fail after 10 s more), and relaunched from the `EXIT` trap so an error midway still brings it back. `--no-relaunch` leaves it quit.
- Never use Desktop's own Log out to change accounts; it may revoke the saved token server-side. `add` signs out locally by deleting the three keys and the cookie files instead.
- `usage` is the one terms-gray-area feature: it decrypts saved tokens with the Keychain key and reads Anthropic's OAuth usage endpoint outside the app. It stays opt-in, read-only, never a trigger for an automatic switch. The CLI runs it only when asked; the menu bar app polls `usage --json` only after the user turns usage on, at an interval of at least 5 minutes, one `security` call per run, and on Refresh at most once per 30 seconds. The app's snapshot poll (`list --json`) reads `config.json` and `meta.json`, never the Keychain. The CLI login swap reads and writes the Keychain too, inside `save`, `add`, `switch`, `rename`, `remove` and the backup prune only, for the CLI item and the tool's own items; `list`, `show`, `current` and `doctor` never call `security`. Still rejected: any automatic switch; usage polling that is on by default or faster than 5 minutes; a launch agent or daemon separate from the user-visible app; reading the Keychain anywhere else; a CLI token in output or in a log, or on any command line but `security`'s own `add-generic-password -X <hex>` for a line too long for `security -i` (Claude Code's own writer). The bearer token goes to `curl` on stdin; the derived AES key is on the `openssl` command line only for the moment of each decrypt.
- Profiles are per Mac: the Safe Storage key is in that Mac's login Keychain, so a copied profile won't decrypt elsewhere, and the CLI tokens are in that Keychain, not in the folder.

## Release

`git tag -a vX.Y.Z` after updating `CHANGELOG.md`, `version=` in `bin/claude-multipass` and `package.json` (the gate fails when the two differ), then `git push --follow-tags`; the tag runs `release.yml`, which publishes the DMG. The Homebrew formula lives in `github.com/jrmatherly/homebrew-tap` as `Formula/claude-multipass.rb` and needs the new tag's tarball `url` and `sha256`; the cask `Casks/claude-multipass-app.rb` then needs the new `version` and the DMG's `sha256` from the release asset. The exact steps are in `.claude/skills/release/SKILL.md`.

## Path-scoped rules

`.claude/rules/` loads when matching files are touched: `desktop-internals.md` (the verified facts, on `bin/**`, `test/**`, `raycast/**`), `safety-and-terms.md` (rails and terms posture, on `bin/**`, `docs/**`, `README.md`), `testing.md` (self-check structure, on `test/**`, `.claude/hooks/**`). Skills: `release`, `docs-audit` (forks the `docs-auditor` agent, which reads and runs read-only commands, never edits).

- Never commit code to `main`. Every change to the script, the app, the tests, the hooks, the scripts or the workflows, a one-line fix included, goes on its own branch in its own git worktree, becomes a pull request against `main`, and lands only through that PR after CI (`check.yml`) is green.
