# Testing

## The self-check, `test/claude-multipass.sh`

One bash script, run by `pnpm check` and on its own (`bash test/claude-multipass.sh`). It exits 1 at the first failed assertion, naming it with the expected and actual values, and prints `ok: <name>` per passing case. `set -euo pipefail`, a temp dir removed by an `EXIT` trap.

Helpers:

- `check <name> <expected> <actual>`: string equality, so pass the actual value as `"$(...)"`.
- `check_true <name> <command...>`: the command's exit status.
- `exit_code <command...>`: prints the status, output discarded, for `check "..." 3 "$(exit_code cda sync)"` (a refusal exits 3).
- `cda`: runs the script under test.

Isolation, so no case can touch the real Desktop:

- `CLAUDE_DESKTOP_DIR`, `CLAUDE_MULTIPASS_DIR`, `CLAUDE_CLI_CONFIG` (`$tmp/claude.json`) and `CLAUDE_CLI_HOME` (`$tmp/claude-home`) point into the temp dir; `HOME` stays untouched. The script reads all four, and `migrate_store` never runs when `CLAUDE_MULTIPASS_DIR` is set.
- Stubs on PATH: `pgrep` exits 1 (Desktop "not running", so the quit is a no-op) or 0 for the refusal cases; `osascript`, `pkill` and `open` append their arguments to `$tmp/calls` (so "relaunched" is `open -a Claude` in that file and "not launched" is the file missing); `fzf` is rewritten per case (pick a row, exit 130 for esc); `security` is stateful: items live in `$tmp/keychain/<service>/<account>`, `add-generic-password -X <hex>` decodes the hex into one, from a `security -i` stdin line or from argv, `find-generic-password -w` prints it (as hex when it holds a non-printable byte, like the real tool) or exits 44, `delete-generic-password` exits 44 when absent, the `Claude Safe Storage` read answers the fixture password for `usage`, and `SECURITY_FAIL_ADD`, `SECURITY_FAIL_FIND` and `SECURITY_FAIL_DELETE` make a write, the CLI item's read or a delete fail; it logs every argv and every stdin line to `$tmp/security-calls` (the `doctor` case asserts the line count does not grow, the token cases that no token appears there, the route cases which of `stdin` and argv carried a write); `kc_get`, `kc_put <service> <account> <value>` and `kc_delete` are the fixture's helpers; `curl` records its arguments and stdin to `$tmp/curl-args` and prints a fixture body plus an HTTP code; `claude` is written per case for `claude auth status`: signed in to the restored org (it also records which CLI locks are held when it runs), another org, signed out (its JSON plus exit 1, as the real CLI does), exit 3 with no output, and output that is not JSON. The quit-fallback case swaps in a `pgrep` that reports Claude until `pkill` runs (or never), and a `sleep` stub that skips the 0.5 s polls, so the 8 s and 10 s waits cost nothing. No app is quit or launched, no Keychain or network is touched.
- Fixture layout: `$d` is the Desktop folder with a tab-indented `config.json` carrying non-login keys (`theme`, `windowBounds`, a UTF-8 string) that must survive byte-identical; `$p/<name>/` profiles; `$b/` backups; `$s/<account>/<org>/local_*.json` pointers with `lastActivityAt`, a `deleted_*` tombstone and an mtime-only pair for the fallback. `$tmp/claude.json` is the CLI's config file, `$tmp/claude-home` its home (the lock dirs), `$tmp/keychain/` the stub's items.
- The `usage` case encrypts a fixture token cache the way the app does (`v10` + AES-128-CBC with the PBKDF2 key of the stub password, IV 16 spaces, base64) and asserts the token never appears in `curl`'s argv or in the output.
- The migration case runs with `CLAUDE_MULTIPASS_DIR` unset and `XDG_CONFIG_HOME` pointed at a temp home, not `HOME`: tools on PATH (jq, fzf, python3) read their own config from `HOME`, and changing it would change their behaviour mid-test.
- A real terminal for the bare invocation comes from `script -q /dev/null`.
- The Raycast cases run `raycast/*.sh`, which put Homebrew's bin first on PATH and run `$CLAUDE_MULTIPASS_BIN`, else `claude-multipass` by name. The fixture exports `CLAUDE_MULTIPASS_BIN` as the checkout's script, and the Raycast switch case asserts its CLI write reached the `security` stub. Without it an installed tool would run against the fixture environment and, with a version that reaches the Keychain some other way, the real Keychain.

Rules:

- Every new command, option or refusal gets a case, and so does every reproduced defect (the `--force` refusals, the empty pointer set under bash 3.2, the mtime prefilter hiding a newer `lastActivityAt`).
- Assert what the user observes: file contents, modes, exit codes, printed lines, which stubs were called. Not internals.
- bash 3.2 is the target (the shebang is `/bin/bash`). It mis-parses escaped quotes nested in `$(...)`, so build such strings in a variable first. BSD tools: `stat -f %Lp`, `date -r`, no `head -n -N`.

## The hook self-checks

Each hook in `.claude/hooks/` has a `test-<hook>.sh` beside it, and `test-settings.sh` checks the wiring in `.claude/settings.json`. `pnpm check` runs every `.claude/hooks/test-*.sh` by glob, so a new self-check needs no edit to `test/check.sh`, only an allow rule in `.claude/settings.json` (`test-settings.sh` fails without one):

- `test-lint-edited.sh` feeds `lint-edited.sh` sample PostToolUse payloads against the real checkout: a Markdown file gets formatted, a bash syntax error in a gated `test/` file exits 2 with `bash -n` itself named in the report, a missing file, a gitignored file and a file in a repo without this hook are skipped, a file in this checkout is linted whatever `CLAUDE_PROJECT_DIR` says (the hook scopes by the file's own checkout, since that variable stays at the session root inside a worktree), a non-bash `bin/` file is left unmodified, a Serena `relative_path` works, a `.sh` outside the gate's list is formatted but not shellchecked, a `bin/` script, `raycast/*.sh` or `scripts/*.sh` with a warning exits 2, a worktree of a throwaway repo whose copy of the hook differs gets the payload handed to its copy (a stub that records stdin, so a branch editing the hook lints with its own version), and a differing copy in another repo is never run.
- `test-lint-bash-edits.sh` feeds `lint-bash-edits.sh` payloads with and without `tool_response.bashEditDiff` (Claude Code records that list in every permission mode only because `.claude/settings.json` sets `bashEditDiffEnabled`; without it, only auto and bypass mode sessions carry it): a `skipped` list is ignored, more than 25 files asks for `pnpm check` instead of linting, each listed file (paths with spaces included) reaches `lint-edited.sh`, gitignored and deleted files are skipped, a missing or crashing `lint-edited.sh` is handled, and a string `tool_response` is not an error.
- `test-settings.sh` checks `.claude/settings.json` with `jq`. `bashEditDiffEnabled` is true. `PreToolUse` has one `Bash` entry, a single `commit-gate.sh` hook with `onFailure` `block`. The `PostToolUse` matcher that runs `lint-edited.sh` matches `Edit`, `Write` and `mcp__serena__replace_content` and not `Bash`, and a `Bash` entry runs `lint-bash-edits.sh`. Every hook command is a `${CLAUDE_PROJECT_DIR}` path to an executable file in the checkout. Every `allow` and `ask` entry is a `Bash(` rule. The permission rules are checked by behaviour: a small matcher applies Claude Code's documented Bash rule semantics (`*` is any text, a trailing ` *` that is the only wildcard also matches the bare command) to sample commands. `switch`, `add`, `save`, `remove`, `rename`, `sync`, `usage` and `pick` must hit `ask` by name, as `bin/`, `./bin/`, `bash bin/`, an absolute path and `bash test/../bin/claude-multipass`, and so must the bare tool and `raycast/switch-claude-account.sh`; `list`, `show`, a lint of the script and a commit message naming a command must not, and a quoted path to the script must still ask. `allow` must cover every `.claude/hooks/test-*.sh` and `bash test/claude-multipass.sh` but not a `test/../` path. `allow` holds `Bash(pnpm check *)`, and there is no `deny` rule. The matcher is the docs' reading, not Claude Code's own code, so a rule shape it does not model (a `:*` suffix) needs a check of its own.
- `test-commit-gate.sh` builds a throwaway git repo that ships a copy of the hook and stubs `pnpm` to exit per a state file. It checks that a non-commit command runs no check, a failing check blocks with exit 2, the commit forms it must gate are gated: `cd` then commit, `git -C`, env prefixes, chains (`&&`, `;`, `|`, a background `&`), subshells, `{ }` groups, `$(...)` and backticks, `if`/`then` bodies, wrappers such as `env`, `command`, `time`, `sudo`, `xargs` and `bash -c`, a wrapper option with a separate value (`nice -n 10`, `sudo -n -u root`: after a wrapper every word up to `git` is skipped, so `bash -c "echo git commit"` gates too, which costs only a check), git options before the subcommand, and the `--continue` of `merge`, `cherry-pick`, `revert`, `rebase` and `am`. A `git -C` in an earlier segment does not move a later commit's target, and a `cd` inside a subshell does not move a commit after it closes. The others are not gated: `commit` as an argument (`git log --grep commit`, also behind `sudo`), and a plain `merge`, `rebase`, `cherry-pick`, `revert` or `pull`, whose resulting tree is not on disk when the gate runs. It also checks that the docs-mirror reminder appears when `bin/claude-multipass` changed alone and not when `docs/` changed too, a worktree of the repo whose copy of the hook differs is gated by that copy (a failing check blocks), a differing copy in another repo is never run, and a foreign repo or one without the hook is never gated.

The commit gate is wired with `timeout: 600` and `onFailure: "block"`. Claude Code's hooks docs list a timeout as a failure, so a check that runs past 600 s blocks the commit (the error says `timed out`) rather than letting it through. This is from the docs, not a measured run.

A change to a hook edits its self-check in the same commit. The hooks run inside Claude Code only; the self-checks are how they get exercised in CI.
