# Testing

## The self-check, `test/claude-multipass.sh`

One bash script, run by `pnpm check` and on its own (`bash test/claude-multipass.sh`). It exits 1 at the first failed assertion, naming it with the expected and actual values, and prints `ok: <name>` per passing case. `set -euo pipefail`, a temp dir removed by an `EXIT` trap.

While iterating, `bash test/claude-multipass.sh <filter>` runs `setup` and either the section of that name or every section whose text holds the string, so a case's name works too. A section is everything from one `#@ <name>` line to the next, and `#@ <name> needs <earlier sections>` runs those first, because most cases lean on the state the ones before them left. A filter that matches nothing exits 2 and lists the sections. `pnpm check` and CI run the whole file, and a new section is proved alone with its own filter before it counts. Section times, measured 2026-11-03: `prune` 4 s, `runlock` 4 s, `refusals` 4 s, `hindsight` 17 s, `switch` 24 s, `debug` 39 s, `doctor` 50 s.

Helpers:

- `check <name> <expected> <actual>`: string equality, so pass the actual value as `"$(...)"`.
- `check_true <name> <command...>`: the command's exit status.
- `exit_code <command...>`: prints the status, output discarded, for `check "..." 3 "$(exit_code cda sync)"` (a refusal exits 3).
- `cda`: runs the script under test.

Isolation, so no case can touch the real Desktop:

- `CLAUDE_DESKTOP_DIR`, `CLAUDE_MULTIPASS_DIR`, `CLAUDE_CLI_CONFIG` (`$tmp/claude.json`) and `CLAUDE_CLI_HOME` (`$tmp/claude-home`) point into the temp dir; `HOME` stays untouched. The script reads all four, and `migrate_store` never runs when `CLAUDE_MULTIPASS_DIR` is set.
- The Hindsight cases run real background sleeps as the daemon and its `claude`, so the script's `kill` really stops them; their `pgrep` stub names those pids, and the `security`, `open` and llmr stubs record the daemon's state at each call. One case runs the real `/usr/bin/pgrep -f` with the pattern taken from the script, on its own fixtures. It only reads pids, since a real daemon may match too.
- Stubs on PATH: `pgrep` exits 1 (Desktop "not running", so the quit is a no-op) or 0 for the refusal cases; `osascript`, `pkill` and `open` append their arguments to `$tmp/calls` (so "relaunched" is `open -a Claude` in that file and "not launched" is the file missing); `fzf` is rewritten per case (pick a row, exit 130 for esc); `security` is stateful: items live in `$tmp/keychain/<service>/<account>`, `add-generic-password -X <hex>` decodes the hex into one, from a `security -i` stdin line or from argv, `find-generic-password -w` prints it (as hex when it holds a non-printable byte, like the real tool) or exits 44, `delete-generic-password` exits 44 when absent, the `Claude Safe Storage` read answers the fixture password for `usage`, `SECURITY_FAIL_ADD`, `SECURITY_FAIL_FIND` and `SECURITY_FAIL_DELETE` make a write, the CLI item's read or a delete fail, and `SECURITY_WAIT=<file>` holds the CLI item's read (marking `<file>.held`) until the file is gone, for the run-lock race; it logs every argv and every stdin line to `$tmp/security-calls` (the `doctor` case asserts the line count does not grow, the token cases that no token appears there, the route cases which of `stdin` and argv carried a write); `kc_get`, `kc_put <service> <account> <value>` and `kc_delete` are the fixture's helpers; `xcode-select` answers a path, or exits 2 for the case without the Command Line Tools; `curl` records its arguments and stdin to `$tmp/curl-args` and prints a fixture body plus an HTTP code; `claude` is written per case for `claude auth status`: signed in to the restored org (it also records which CLI locks are held when it runs), another org, signed out (its JSON plus exit 1, as the real CLI does), exit 3 with no output, and output that is not JSON. The quit-fallback case swaps in a `pgrep` that reports Claude until `pkill` runs (or never), and a `sleep` stub that skips the 0.5 s polls, so the 8 s and 10 s waits cost nothing. `CLAUDE_MULTIPASS_LLMR` points at an `llmr` stub that records its environment to `$tmp/llmr-env`, logs its argv to `$tmp/llmr-calls` and `$tmp/calls`, exits with the status in `$tmp/llmr-fail`, and marks its Desktop up; in the LLMR cases `pgrep` answers `-axq Claude` and the exact `-aqf -- --user-data-dir=.*/claude-app-user-data/` pattern from marker files, and the `osascript` stub removes them. The `~/.llm-router/bin/llmr` fallback case runs with `HOME` in the temp dir and a `PATH` that holds no `llmr`. No app is quit or launched, no Keychain or network is touched.
- `cda_stdin` runs the script with `jq` and `cat` wrappers first on PATH that log their stdin's file type to `$tmp/stdin-types`; a here-string shows as `Regular File` (a temp file on disk under bash 3.2), a pipe as `Fifo File`. The wrappers drop their own dir from PATH before `exec`, since a version-manager shim looks the tool up again.
- Fixture layout: `$d` is the Desktop folder with a tab-indented `config.json` carrying non-login keys (`theme`, `windowBounds`, a UTF-8 string) that must survive byte-identical; `$p/<name>/` profiles; `$b/` backups; `$s/<account>/<org>/local_*.json` pointers with `lastActivityAt`, a `deleted_*` tombstone and an mtime-only pair for the fallback. `$tmp/claude.json` is the CLI's config file, `$tmp/claude-home` its home (the lock dirs), `$tmp/keychain/` the stub's items.
- The `usage` case encrypts a fixture token cache the way the app does (`v10` + AES-128-CBC with the PBKDF2 key of the stub password, IV 16 spaces, base64) and asserts the token never appears in `curl`'s argv or in the output.
- The migration case runs with `CLAUDE_MULTIPASS_DIR` unset and `XDG_CONFIG_HOME` pointed at a temp home, not `HOME`: tools on PATH (jq, fzf, python3) read their own config from `HOME`, and changing it would change their behaviour mid-test.
- A real terminal for the bare invocation comes from `script -q /dev/null`.
- The fixture's `PATH` is `$tmp/bin`, `/usr/bin`, `/bin` and `jq`'s folder, never the caller's, because a real `claude` reads the real login and rewrites `~/.claude.json`. A `jq` folder that holds a `claude` fails the "no-claude PATH" check before any case runs. `/usr/bin` comes before `jq`'s folder because that folder can be a version manager's shims: a mise shim cost 36 ms a call against 8 ms for `/usr/bin/jq` (M, 2026-11-03, each through `sh`), and moving it took the whole file from 350 s to 129 s.
- A default `sleep` stub on `PATH` skips the script's 1 s lock retries and turns the lock toucher's 3 s tick into 0.3 s. A case that writes its own `sleep` stub removes it, which leaves the real `sleep` for the cases after it. `stat`'s mtime has 1 s steps, so the toucher cases wait at least a second and a tick: `SECURITY_HOLD` holds the CLI item's read for 2 s and the killed-run case compares mtimes 1.5 s apart. Breaking the toucher's `touch` or its `kill -0 $$` still fails these cases (mutation run, 2026-11-03).
- Every `open` stub starts with `export PATH="$tmp/bin:$PATH"`, because `desktop_launch` runs `open` under `env -i`, which drops the fixture's `PATH`, and an unexported assignment does not reach a child `sh`. Without that line, a `security` call in the stub or its child is the real `/usr/bin/security`, and the debug cases' `dbg-at-open` would overwrite the live `Claude Code-credentials` item. Never remove the line and run the file. Prove it on a scratch copy with `security` replaced by a logger.
- The fixture unsets `CLAUDE_MULTIPASS_DEBUG`, `CLAUDE_CONFIG_DIR` and `CLAUDE_SECURESTORAGE_CONFIG_DIR` and exports `TERM=dumb` beside its exports, so the caller's environment cannot fail the gate. Either config variable blocks the CLI-move cases, an inherited debug variable fails `the config lock is touched while held` and a color `TERM` wraps warnings in `tput` codes, which fails `current warns when the gateway does not answer`.
- The debug cases stub `pgrep -x claude` to name a real background process whose command holds a token past 160 characters, `open` to record its environment to `$tmp/open-env` and run `$tmp/dbg-at-open` (a late writer of the CLI item), and `sleep` to count and skip the watch's 2 s polls. A `$tmp/security-find-fail` file makes a read of the CLI item exit 36, for a failure after the arm, which `SECURITY_FAIL_FIND` cannot time.
- The Raycast cases run `raycast/*.sh`, which put Homebrew's bin first on PATH and run `$CLAUDE_MULTIPASS_BIN`, else `claude-multipass` by name. The fixture exports `CLAUDE_MULTIPASS_BIN` as a wrapper that puts the fixture's `PATH` back and runs the checkout's script, so a `claude` or `curl` in Homebrew's bin never answers, and the Raycast switch case asserts its CLI write reached the `security` stub. Without it an installed tool would run against the fixture environment and, with a version that reaches the Keychain some other way, the real Keychain.

Rules:

- Every new command, option or refusal gets a case, and so does every reproduced defect (the `--force` refusals, the empty pointer set under bash 3.2, the mtime prefilter hiding a newer `lastActivityAt`).
- Assert what the user observes: file contents, modes, exit codes, printed lines, which stubs were called. Not internals.
- bash 3.2 is the target (the shebang is `/bin/bash`). It mis-parses escaped quotes nested in `$(...)`, so build such strings in a variable first. BSD tools: `stat -f %Lp`, `date -r`, no `head -n -N`.

## The hook self-checks

Each hook in `.claude/hooks/` has a `test-<hook>.sh` beside it, and `test-settings.sh` checks the wiring in `.claude/settings.json`. `pnpm check` runs every `.claude/hooks/test-*.sh` by glob, so a new self-check needs no edit to `test/check.sh`, only an allow rule in `.claude/settings.json` (`test-settings.sh` fails without one):

- `test-lint-edited.sh` feeds `lint-edited.sh` sample PostToolUse payloads against the real checkout: a Markdown file gets formatted, a bash syntax error in a gated `test/` file exits 2 with `bash -n` itself named in the report, a missing file, a gitignored file and a file in a repo without this hook are skipped, a file in this checkout is linted whatever `CLAUDE_PROJECT_DIR` says (the hook scopes by the file's own checkout, since that variable stays at the session root inside a worktree), a non-bash `bin/` file is left unmodified, a Serena `relative_path` works, a `.sh` outside the gate's list is formatted but not shellchecked, a `bin/` script, `raycast/*.sh` or `scripts/*.sh` with a warning exits 2, a worktree of a throwaway repo whose copy of the hook differs gets the payload handed to its copy (a stub that records stdin, so a branch editing the hook lints with its own version), and a differing copy in another repo is never run.
- `test-lint-bash-edits.sh` feeds `lint-bash-edits.sh` payloads with and without `tool_response.bashEditDiff` (Claude Code records that list in every permission mode only because `.claude/settings.json` sets `bashEditDiffEnabled`; without it, only auto and bypass mode sessions carry it): a `skipped` list is ignored, more than 25 files asks for `pnpm check` instead of linting, each listed file (paths with spaces included) reaches `lint-edited.sh`, gitignored and deleted files are skipped, a missing or crashing `lint-edited.sh` is handled, and a string `tool_response` is not an error.
- `test-settings.sh` checks `.claude/settings.json` with `jq`. `bashEditDiffEnabled` is true. `PreToolUse` has one `Bash` entry, a single `commit-gate.sh` hook with `onFailure` `block`. The `PostToolUse` matcher that runs `lint-edited.sh` matches `Edit`, `Write` and `mcp__serena__replace_content` and not `Bash`, and a `Bash` entry runs `lint-bash-edits.sh`. Every hook command is a `${CLAUDE_PROJECT_DIR}` path to an executable file in the checkout. Every `allow` and `ask` entry is a `Bash(` rule. The permission rules are checked by behaviour: a small matcher applies Claude Code's documented Bash rule semantics (`*` is any text, a trailing ` *` that is the only wildcard also matches the bare command) to sample commands. `switch`, `add`, `save`, `remove`, `rename`, `sync`, `usage` and `pick` must hit `ask` by name, as `bin/`, `./bin/`, `bash bin/`, an absolute path, `bash test/../bin/claude-multipass` and the copy inside the app, and so must the bare tool and `raycast/switch-claude-account.sh`; `list`, `show`, the copy's `--version`, a lint of the script and a commit message naming a command must not, and a quoted path to the script must still ask. `allow` must cover every `.claude/hooks/test-*.sh` and `bash test/claude-multipass.sh` but not a `test/../` path. `allow` holds `Bash(pnpm check *)`, and there is no `deny` rule. The matcher is the docs' reading, not Claude Code's own code, so a rule shape it does not model (a `:*` suffix) needs a check of its own.
- `test-commit-gate.sh` builds a throwaway git repo that ships a copy of the hook and stubs `pnpm` to exit per a state file. It checks that a non-commit command runs no check, a failing check blocks with exit 2, the commit forms it must gate are gated: `cd` then commit, `git -C`, env prefixes, chains (`&&`, `;`, `|`, a background `&`), subshells, `{ }` groups, `$(...)` and backticks, `if`/`then` bodies, wrappers such as `env`, `command`, `time`, `sudo`, `xargs` and `bash -c`, a wrapper option with a separate value (`nice -n 10`, `sudo -n -u root`: after a wrapper every word up to `git` is skipped, so `bash -c "echo git commit"` gates too, which costs only a check), git options before the subcommand, and the `--continue` of `merge`, `cherry-pick`, `revert`, `rebase` and `am`. A `git -C` in an earlier segment does not move a later commit's target, and a `cd` inside a subshell does not move a commit after it closes. The others are not gated: `commit` as an argument (`git log --grep commit`, also behind `sudo`), and a plain `merge`, `rebase`, `cherry-pick`, `revert` or `pull`, whose resulting tree is not on disk when the gate runs. It also checks that the docs-mirror reminder appears when `bin/claude-multipass` changed alone and not when `docs/` changed too, that the changelog reminder appears when `bin/` or `app/Sources/` changed without `CHANGELOG.md` (alone for an `app/Sources/` change) and not once `CHANGELOG.md` changed too, a worktree of the repo whose copy of the hook differs is gated by that copy (a failing check blocks), a differing copy in another repo is never run, and a foreign repo or one without the hook is never gated.

The commit gate is wired with `timeout: 600` and `onFailure: "block"`. Claude Code's hooks docs list a timeout as a failure, so a check that runs past 600 s blocks the commit (the error says `timed out`) rather than letting it through. This is from the docs, not a measured run.

A change to a hook edits its self-check in the same commit. The hooks run inside Claude Code only; the self-checks are how they get exercised in CI.
