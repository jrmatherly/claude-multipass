---
name: release
description: Cut a claude-multipass release. Tags the repo, pushes (release.yml builds, signs, notarizes and uploads the menu bar app DMG), bumps the Homebrew formula in jrmatherly/homebrew-tap to the new tag's tarball and sha256, then the cask to the DMG. Use for "cut a release", "bump the formula", "tag vX.Y.Z", or "release X.Y.Z".
argument-hint: '<X.Y.Z | next>'
disable-model-invocation: true
---

Release version `$ARGUMENTS` (write it as `X.Y.Z` below; the tag is `vX.Y.Z`). When it is not `^[0-9]+\.[0-9]+\.[0-9]+$` ("next", "our next version"), derive it from `## Unreleased` in `CHANGELOG.md` against the current `version=`: a new feature or a changed setting bumps the minor and zeroes the patch, fixes only bump the patch. Say which version you chose and why before going on. Stop when `## Unreleased` is missing or empty, since there is nothing to release.

Preconditions: on `main`, clean tree, `HEAD` equals `origin/main` (`git fetch origin && test "$(git rev-parse HEAD)" = "$(git rev-parse origin/main)"`; `release.yml` refuses a tag on a commit that is not on `main`, and a local `main` behind `origin/main` tags an older commit), `main`'s CI passed on `HEAD` (`gh run list --workflow check.yml --branch main --limit 1 --json headSha,conclusion` shows `HEAD`'s SHA and `success`; a cancelled run, which a later push causes, counts as not passed, so rerun it with `gh run rerun <id>`), the tap is cloned at `~/dev/homebrew-tap` (`ls ~/dev/homebrew-tap/Formula/claude-multipass.rb ~/dev/homebrew-tap/Casks/claude-multipass-app.rb`), and `gh secret list` shows the six secrets `release.yml` needs: five copied by name from the ai-kb repository settings, `MACOS_CERT_P12` (base64 of the Developer ID .p12), `MACOS_CERT_PASSWORD`, `APPLE_API_KEY_ID`, `APPLE_API_ISSUER_ID`, `APPLE_API_KEY_P8` (the .p8 contents), and `SPARKLE_ED_KEY` (the EdDSA seed whose public key is in `scripts/build-app.sh`). Without all six, or when the tag differs from `package.json`'s version or from the top `CHANGELOG.md` heading, the workflow fails before building. Casks and formulae from a third-party tap load only after `brew trust jrmatherly/tap` (once per Mac; `brew audit --cask` and a bare `brew install` refuse otherwise; `brew bundle` with `trusted: true` on the line does it itself, which is how the dotfiles Brewfile installs them).

1. Check that `main` already carries the release: `CHANGELOG.md` has a `## X.Y.Z (YYYY-MM-DD)` section at the top (no `v`, matching the existing headings; a `## Unreleased` heading becomes the dated one) and `version=` in `bin/claude-multipass` equals `"version"` in `package.json` equals `X.Y.Z`. Those edits are code and land through a PR like any other (CLAUDE.md, Custom Notes), so a release never commits on `main`: when they are missing, open that PR first. Running `/release` is Jason's standing approval to merge that version-bump PR once its `check` passes, and nothing else. The PR:

   - `git fetch origin && git worktree add -b release-X.Y.Z ../claude-multipass-wt-release origin/main`, then `pnpm install` in it.
   - Set `version=X.Y.Z` in `bin/claude-multipass` and `"version": "X.Y.Z"` in `package.json`, and turn `## Unreleased` into `## X.Y.Z (YYYY-MM-DD)` (today's local date). Run `node_modules/.bin/prettier --check CHANGELOG.md`.
   - Commit `Release X.Y.Z`, push, `gh pr create`. A just-created PR can have no checks registered yet, so wait about 15 s before `gh pr checks <n> --watch`.
   - When `check` passes: `gh pr merge <n> --squash --delete-branch` (it removes the worktree too), then `git checkout main && git pull --ff-only` and recheck the Preconditions.

2. Tag: `git tag -a vX.Y.Z -m "vX.Y.Z"`.
3. Push the tag: `git push --follow-tags`. A tag push prints no `Bypassed rule violations` line (none on v0.5.2 or v0.6.0; the `protect main` bypass notice appears on docs-only pushes to `main`, not on tags). Quote whatever the push prints in the report, unfiltered. The tag starts `release.yml`; wait with `gh run watch --exit-status <run id>` (`gh run list --workflow release.yml --limit 1` finds it). It publishes `claude-multipass-app_X.Y.Z_arm64.dmg`, its `.sha256` and `appcast.xml` on the GitHub release (the suffix is the runner's `uname -m`; the build job runs on `macos-26`, which is arm64). Confirm all three are there: `gh release view vX.Y.Z --json assets -q '.assets[].name'`. Confirm the DMG is notarized: download it and run `spctl -a -vv -t open --context context:primary-signature <dmg>`, expected `accepted`. The app inside carries its own stapled ticket: mount the DMG and run `xcrun stapler validate "/Volumes/Claude Multipass/Claude Multipass.app"`, expected `The validate action worked!`. The workflow never replaces a published asset; a rerun against a release that already has any of the three fails, so republishing means deleting that asset by hand first.
4. Compute the tarball digest (GitHub builds the archive from the tag; wait for the push to land):

   ```sh
   curl -sL https://github.com/jrmatherly/claude-multipass/archive/refs/tags/vX.Y.Z.tar.gz | shasum -a 256
   ```

5. Edit `~/dev/homebrew-tap/Formula/claude-multipass.rb`: set `url` to `https://github.com/jrmatherly/claude-multipass/archive/refs/tags/vX.Y.Z.tar.gz` and `sha256` to the digest.
6. Audit the formula: `brew audit --strict --formula jrmatherly/tap/claude-multipass`. Fix what it reports before going on. `brew audit` reads Homebrew's own clone of the tap (`$(brew --repo)/Library/Taps/jrmatherly/homebrew-tap`), not `~/dev/homebrew-tap`, so without step 8's commit in that clone it passes on the old version (measured on 0.10.0). Run both audits after committing in `~/dev/homebrew-tap` and before pushing: `git -C "$(brew --repo)/Library/Taps/jrmatherly/homebrew-tap" pull --ff-only ~/dev/homebrew-tap main`.
7. Edit `~/dev/homebrew-tap/Casks/claude-multipass-app.rb`: set `version` to `X.Y.Z` and `sha256` to the digest in the release asset `claude-multipass-app_X.Y.Z_arm64.dmg.sha256`. The formula is bumped first (step 5) so that the app never lands ahead of its tool. Audit it, as step 6 says: `brew audit --cask --strict jrmatherly/tap/claude-multipass-app`. The cask token is `claude-multipass-app`, not the formula's name, so `brew install jrmatherly/tap/claude-multipass` keeps meaning the tool; if the audit ever reports a token clash, rename it to `claude-multipass-menubar` and record why here. Then fetch the feed: `gh release download vX.Y.Z -p appcast.xml -O ~/dev/homebrew-tap/appcast.xml --clobber && git -C ~/dev/homebrew-tap add appcast.xml` (the `add` because step 8's `commit -am` skips an untracked file, and 0.10.0 adds it for the first time). Assert that `<sparkle:version>` in it and the cask's `version` both equal `X.Y.Z`.

   7a. The gate, skipped for 0.10.0 because nothing can self-update yet. The feed has not moved, so no installed app is offered this version, but the DMG is already public at `/releases/latest`. A failure here stops the release: run `gh release edit vX.Y.Z --prerelease`, which takes it off that link, and `git -C ~/dev/homebrew-tap reset --hard` to drop the tap edits. Jason runs it on his Mac, with the installed app quit and the app from a browser-downloaded DMG of the previous version copied to `~/Applications`:

   - `defaults write net.matherly.claude-multipass SUFeedURL https://github.com/jrmatherly/claude-multipass/releases/download/vX.Y.Z/appcast.xml`. The asset is already on the release, so no server is needed.
   - Open that copy, Check now, then Update and relaunch. Expect the new version.
   - `defaults delete net.matherly.claude-multipass SUFeedURL`, whether the update passed or failed, or that app stays pointed at this one release.
   - Delete the `~/Applications` copy, reopen the installed app, and confirm that Launch at login still reads on, since two copies share one bundle id.

8. Commit the tap, audit as step 6 says, then push: `git -C ~/dev/homebrew-tap commit -am "claude-multipass vX.Y.Z"`, the audits, `git -C ~/dev/homebrew-tap push`. This commit carries `appcast.xml`, so it is the announcement: every installed app sees the offer at its next check. To roll back, `git revert` the tap commit and push. New offers stop, and an offer already on screen clears at that app's next successful check.
9. Upgrade through the app, which is the real test of the cask route: open About on the old running app, Check now, then Update and relaunch. `raw.githubusercontent.com` caches the feed for up to 300 s, so Up to date in the first five minutes after step 8 means wait and check again. That upgrades the formula and the cask. The manual route stays as the fallback, and for 0.10.0, whose previous version has no updater: `brew update && brew upgrade claude-multipass && brew install --cask jrmatherly/tap/claude-multipass-app` (or `brew upgrade --cask`).
10. Verify: `claude-multipass --version` prints `claude-multipass X.Y.Z`, `claude-multipass list` prints the saved accounts, `brew info jrmatherly/tap/claude-multipass` shows `X.Y.Z`, and the app is relaunched (`pkill -x ClaudeMultipass; open -a 'Claude Multipass'`) so the installed bundle is the one running, and Settings, General still reads Launch at login on. The real switch is Jason's, never the agent's: ask him to switch from the popover or an outside terminal and run `claude auth status` in a new terminal, and report what he sees.

Report the tag, the digest, the DMG digest, the tap commit, and the output of step 10. A failed audit or a digest mismatch stops the release; nothing is retagged. If the tag must move, delete it locally and remotely first (`git tag -d vX.Y.Z && git push origin :refs/tags/vX.Y.Z`), and say so, since the published tarball changes. The `protect release tags` ruleset blocks updating or deleting a `v*` tag for everyone but repository admins, so only Jason can do this.
