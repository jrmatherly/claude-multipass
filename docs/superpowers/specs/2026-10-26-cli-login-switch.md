# CLI login switch

`save` and `switch` also capture and restore the Claude Code CLI's terminal login per profile, so one switch moves Claude Desktop and the `claude` command together. Research and measurements from the 2026-10-26 session, revised after two adversarial reviews of the plan; the facts with evidence labels are in `.claude/rules/desktop-internals.md`.

## Problem

A switch moves Desktop's login (three `config.json` keys plus cookies) and nothing else. The CLI keeps its own login: the login-Keychain item with service `Claude Code-credentials` and account equal to the macOS user name (a JSON blob with `claudeAiOauth` tokens), plus the `oauthAccount` object in `~/.claude.json`, which pins the account and org per request. Measured on this Mac: Desktop signed in as one profile while `claude auth status` reports another. The CLI's `accountUuid` in `oauthAccount` is the same claude.ai account id Desktop stores as `lastKnownAccountUuid`, so a profile's `meta.json` `account` already identifies the CLI login that belongs to it.

## Decisions

1. **Where the CLI token lives when saved.** In the Keychain, never on disk: one generic password per profile, service `claude-multipass`, account `<profile name>`. Its value is the account-specific part of the CLI item: `{claudeAiOauth, trustedDeviceToken?}`. The other top-level keys of the CLI item (`mcpOAuth`, `mcpOAuthClientConfig`, `mcpXaaIdp`, `mcpXaaIdpConfig`, `pluginSecrets`) are shared across accounts and stay in the live item. The rails sentence "profiles hold only encrypted tokens" stays true.
2. **What goes in the profile folder.** `cli.json`, mode 0600, holding `{"oauthAccount": {...}}` as read from `~/.claude.json`. It carries no secret. Its presence is what `list --json` reports as `cliSaved`, so the snapshot poll stays Keychain-free.
3. **When the CLI part is captured.** `profile_save` captures it only when the CLI item exists and `oauthAccount.accountUuid` equals the account Desktop is signed in as. Otherwise it saves Desktop only, warns `Claude Code is signed in as a different account, or signed out; saved the Desktop login only`, and leaves any earlier `cli.json` and Keychain item of that profile untouched. The same check guards the re-save of the outgoing profile on `switch`, so a `claude auth login` or `claude auth logout` done by hand never overwrites or deletes a saved login. This is the fingerprint check CCSwitcher does with a token hash; the account uuid makes it free.
4. **Restore.** `profile_restore` on a profile with `cli.json`: when the CLI is already signed in as the target account (two profiles for one account, the "already signed in" repair, a switch back after a legacy target, a hand login), the live tokens are fresher than the saved ones, so the tool re-saves them into the profile and writes nothing to the CLI. Otherwise it backs up the live CLI item and `oauthAccount` (decision 7), writes the CLI item as `(live | del(.claudeAiOauth, .trustedDeviceToken)) + saved` (the saved value alone when there is no live item), then replaces `oauthAccount` in `~/.claude.json`. A profile without `cli.json` restores Desktop only and warns `no CLI login saved for <name>; switched Desktop only`. A `cli.json` whose Keychain item is missing restores Desktop only and warns `the saved CLI login for <name> is missing from the Keychain; run claude auth login, then save <name>`. The "already signed in" path of `switch` repairs the CLI part the same way it repairs the cookies, through the same backup.
5. **Keychain access.** Through `security` on PATH as `usage` does (the fixture stubs it; on a stock Mac that is `/usr/bin/security`, so "Always Allow" persists). Reads: `find-generic-password -a <acct> -s <svc> -w`; exit 44 means absent. Writes: `add-generic-password -U -a <acct> -s <svc> -X <hex>` as one line on stdin through `security -i`, never on argv (the rails forbid a token on a command line; the CLI itself writes the same way). Hex avoids `security -i`'s own quoting rules, which reject the shell's `'\''` escape (measured: exit 45) while a hex value with quotes, backslashes, backticks and `$` round-trips. Measured: `security -i` stores at most 4019 bytes of a longer line and corrupts the rest; the `-w` prompt reads the terminal, not a pipe. So the payload limit is 1900 bytes of JSON (3800 hex plus the command, under 3900, counted under `LC_ALL=C`). The saved per-profile value is a few hundred bytes. A live item whose merged payload would exceed the limit (large shared MCP keys) makes the tool skip the CLI part with `the CLI login is too large for security -i; switched Desktop only`, backup included: nothing is dropped or truncated. Deletes: `delete-generic-password -a -s`, 44 treated as done. Any other `security` failure (a denied prompt, a locked Keychain) is a warning naming the status, and the switch finishes Desktop only.
6. **Locks.** The CLI's locks are directories; `mkdir` succeeding is the acquire, `rmdir` the release, and a holder older than the stale threshold is removed first. Taken right after Desktop quits and before any file changes, retried five times a second apart, so a busy CLI fails the switch before Desktop's config is touched: `$cli_home/.oauth_refresh.lock` (stale after 60 s), `$cli_home.lock` (60 s, the older lock the CLI still takes), then `~/.claude.json.lock` (10 s). Released after the writes and by the `EXIT` trap, where every `rmdir` tolerates an absent dir so the Desktop relaunch always runs. Taken only when the switch or save has a CLI part to do.
7. **Backups.** `backup_login` also copies the live CLI item into Keychain item `claude-multipass` / `login-<timestamp>-<pid>` (the backup folder's name) and the live `oauthAccount` into `backups/login-.../cli.json`. Pruning past ten deletes the matching Keychain items (44 is fine: a folder from 0.2.x has none). `profile_remove` and a forced `save` move the folder to `backups/profile-*` as today and delete the profile's Keychain item; the docs say the CLI token is not recoverable from that backup, the Desktop login is. `profile_rename` re-keys the item: read, add under the new name, delete the old; a 44 on the read means nothing to move.
8. **Verification.** After a restore that wrote the CLI item, when `claude` is on PATH, `switch` runs `claude auth status` and compares `orgId` with the restored `oauthAccount.organizationUuid`; a mismatch is a warning naming the backup folder, not a rollback. No `claude` on PATH, no warning. The menu bar app's PATH gains `$HOME/.local/bin`, where the native `claude` lives, so the check runs from the app too.
9. **Running sessions.** A `claude` process already running keeps its token and can refresh it after the switch, writing the old account's tokens over the new one. After the quit, `switch` and `save` warn `Claude Code is running (pid N); quit it first, or its next token refresh can overwrite the switched login` when `pgrep -x claude` finds one, and the docs say to quit terminal sessions first. The Code tab is unchanged (`desktop-internals.md` line 31).
10. **Paths and scope.** `~/.claude.json` is `${CLAUDE_CLI_CONFIG:-$HOME/.claude.json}` and the CLI home `${CLAUDE_CLI_HOME:-$HOME/.claude}`; the fixture sets both into its temp dir so the real file is never touched (HOME stays, as `testing.md` explains). A missing file or dir means signed out. When `CLAUDE_CONFIG_DIR` is set in the environment the CLI item has a hashed service name; `save` and `switch` skip the CLI part with `CLAUDE_CONFIG_DIR is set; the CLI login is not switched` and `doctor` reports it. The menu bar app never sees the shell's variable, so the check only ever fires from a terminal. No per-account `CLAUDE_CONFIG_DIR`, as `safety-and-terms.md` says. The file fallback `~/.claude/.credentials.json` is not handled.
11. **`add`** stays Desktop-only. Its hint gains "then `claude auth login` for the terminal, then `claude-multipass save <name>`". After a `claude auth login` the next switch away from that account captures the login through the re-save, so no extra `save` is needed; the docs say so.
12. **`doctor`** stays file-only: `warn: <name>: no CLI login saved` per profile without `cli.json`, `warn: CLAUDE_CONFIG_DIR is set; the CLI login is not switched`. "doctor never calls security" holds.
13. **The app shows the script's warnings.** The CLI runner returns stderr alongside stdout on success, and a `switch` or `save` that warned shows the warning text under the row until the next action. Otherwise every "switched Desktop only" would be invisible from the menu bar.
14. **Terms posture.** The CLI token is copied between two items of the same Keychain and only ever used by Claude Code itself; the tool never sends it anywhere. `usage` stays the one gray-area feature. `safety-and-terms.md` is amended to allow `security` reads and writes inside `save`, `add` (through its re-save and backup), `switch`, `rename`, `remove` and the backup prune, for the CLI login item and the tool's own items, and keeps rejecting them anywhere else, with no token on argv, in output or in a log.
15. **Version.** 0.3.0, and the app's version floor rises to 0.3.0 so its CLI-related text is never shown against a tool that lacks the feature (the app already refuses an older tool; README and docs say "0.2.0 or newer" today).

## Not in scope

Refreshing saved tokens outside the CLI (claude-swap posts to the OAuth endpoint; CCSwitcher too). The re-save on switch-away keeps the saved copy fresh as long as switches go through the tool; a saved login the CLI has since rotated past fails with `invalid_grant`, possibly hours later at access-token expiry, and the fix is `claude auth login` then `save`. Rollback on verification failure. The `.credentials.json` fallback. Signing the CLI out in `add`. The first Keychain prompt from the app: `security` may need an "Always Allow" once; a prompt left unanswered for 120 s hits the app's timeout, whose SIGTERM runs the EXIT trap and relaunches Desktop unswitched. Task 10 of the plan observes what happens.
